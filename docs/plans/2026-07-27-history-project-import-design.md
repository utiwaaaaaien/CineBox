# CineBox 历史项目导入与替换设计

## 目标

统一历史项目的展示名称，并允许用户用自己的项目文件替换任一历史项目。替换必须经过“选择文件 → 本地解析 → 内容分析 → 小窗预览 → 用户确认”流程，避免误覆盖。

## 命名规范

历史项目统一显示为“项目类型｜项目名称”。类型取自 CineBox 已支持的项目类型；名称去除重复的类型后缀、文件扩展名和多余空格。用户文件无法识别类型时使用“自定义项目”。

## 交互

历史项目选择区的每一项增加“预览”和“上传替换”入口。预览以小窗口展示项目类型、规模、机位、画面方向、分析摘要及器材清单。上传支持 PDF、XLS/XLSX、CSV、JSON、TXT 和 Markdown，限制单文件 10 MB。

文件解析和分析在浏览器本地完成，原始文件不上传。解析完成后先打开分析预览；只有用户点击“确认替换”才覆盖目标历史项目。自定义项目提供“恢复内置项目”操作。

## 数据流

内置历史项目作为只读基线。用户替换内容以相同槽位 ID 保存为本地覆盖项，页面通过“内置基线 + 本地覆盖”生成当前历史项目列表。分析结果包含规范名称、项目属性、识别出的标准器材 ID、数量、原文件名、解析时间和预览文本。

器材识别优先匹配标准器材名称与别名，并对常见型号进行归一化。未识别内容保留在预览文本中，但不会伪造为标准器材。没有识别出任何器材时不允许确认替换。

## 错误处理

不支持的格式、空文件、加密或无法解析的 PDF、损坏的工作簿、超过大小限制以及未识别器材都提供明确提示。解析期间禁用重复操作。关闭分析窗口不会改变历史项目。

## 验证

为命名规范、文本分析、器材匹配和覆盖项清洗增加单元测试。运行完整构建、测试和 lint；同时确认上传解析依赖按需加载，不增加主页面首屏负担。
