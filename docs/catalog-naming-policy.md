# 器材库命名规范（V5 起）

统一显示名称由四个字段按顺序组成：**中文品牌名 + 英文品牌名 + 系列名称 + 型号及规格**，字段之间使用一个空格。缺少已核验的中文名称时使用官方英文名称；官方未设独立系列的产品可以省略系列字段。禁止为凑齐四段而编造译名或系列。

中文厂商官网、官方中文说明书和官方中文公告优先。缺少中文资料时使用厂商国际官网及官方技术手册。库存表、租赁清单和历史项目只证明曾记录该器材及其规格，不证明名称、品牌归属或官网型号成立。

## 核验状态

| 状态 | 含义 |
| --- | --- |
| 型号已核验 | 产品名称和记录中的基本规格有对应官方资料。记录没有卡口等信息时，核验状态不代表已确认这些缺失规格。 |
| 系列已核验，规格待核验 | 官方资料确认了系列，记录中的具体规格或套装配置仍需核对。 |
| 待核验 | 品牌、型号、版本或原始规格不能由当前官方资料确认，或与资料存在冲突。保留原始信息及疑点。 |
| 通用器材 | 记录描述通用现场用品或功能性附件，没有指定厂商品牌和商品型号。 |

`verified` 仅对应“型号已核验”。每条记录的 `references` 区分品牌、系列和型号来源，并记载资料语言及核验日期。品牌官网首页不能作为单一型号已核验的依据。特调、改装、重新封装或第三方配置需单独核对。

## 去重边界

仅合并分类、品牌、单位及完整规范名称相同的记录。不同焦段、卡口、代际、光圈、滤镜尺寸、密度、渐变方式、改装版本及套装配置分别保留。未记录卡口的镜头与已记录 PL 或 E 卡口的镜头分别保留；缺少光圈的记录也不能通过猜测并入完整规格。

规范处理可以消除大小写、空白、`T2.0` 与 `T2`、尺寸乘号等书写差异。厂商资料明确同一产品后，才可以统一品牌联名、拼写错误或地区名称。旧名称作为搜索别名保留；误归属的名称从错误产品的别名中移出。

合并保留旧 ID 到现有 ID 的映射，旧项目与备份恢复时迁移引用。不同旧 ID 合并到同一器材时合计数量、保留备注；确认状态冲突则改为待确认。原始库存快照保留用于追溯。

## 后续维护

1. 新记录加入 `data/catalog/catalog-additions.json`，已有 V4 库存快照保持冻结；记录稳定 ID、分类、品牌、名称、单位、规格及原始别名。
2. 在 `scripts/catalog-naming.mjs` 补充经过核对的官方品牌名、系列名和型号依据。没有依据的条目保持待核验，不沿用库存表中的 `verified` 值。
3. 执行 `pnpm run catalog:build`，检查 `data-quality-audit.json` 中的合并、品牌修正、恢复项和待核验项。
4. 执行 `pnpm run catalog:check` 和 `pnpm test`。对影响器材身份的变更，检查旧项目、规格差异与 Excel 导出。

`app/equipment-catalog.canonical.ts` 和 `data/catalog/equipment.v5.json` 是生成结果。应用目录、品牌筛选、系列视图、器材单及导出使用同一份规范名称。

## 发布边界与双语显示

发布前先搜索不明确型号、别名与昵称。品牌、系列和焦段能够定位同一产品时，光圈、压缩比、屏幕尺寸等小冲突按厂商官方规格纠正后保留，错误旧称作为别名和审核修正记录保留。不同代际、卡口、改装版本和套组配置不得通过猜测统一。

`published` 表示允许用于选材，与 `verified` 分开。具体库存型号、镜头组、改装配置及通用器材继续可选；按用户确认，只有品牌而没有明确系列的监视器等保留原名称，Lensbaby、万花筒滤镜、炫光孔雀镜等特殊器材保留原名，采集卡、章鱼时码器等辅助功能器材纳入目录。尚缺官方证据的字段保留审核说明，不将可选状态称为全字段核验通过。没有具体型号、尺寸或功率的 RGB 棒灯、LED 布灯及类似笼统灯具移出；具有型号或尺寸的灯具保留。没有搜索结果不能据此断言产品不存在。

明确产品系列的泛称按本次官方目录的最新型号提供新选材项（核对日期 2026-10-07）。最新型号使用新的稳定 ID，旧记录保留原身份并通过 `replacementIds` 指明可选项；不得将旧项目未指定型号的器材自动改成新型号。老蛙第四代探针变焦的两种焦段和光圈分别保留；MP、SP、UP 补全为 ARRI 官方镜头系列，镜头组与单颗焦段分别保留。最新型号是维护时核对的快照，不会自动随厂商发布而变更。

`scripts/catalog-editorial-review.mjs` 与 `data/catalog/editorial-decisions.json` 保存用户确认的例外、最新系列对应及混合别名拆分。新记录仍须经过核对，不通过泛化规则自动把所有模糊名称标为已核验。`unusable` 是实际排除，`superseded-for-selection` 是由新型号或拆分记录提供新选项；统计分别列出。

`scripts/catalog-release-review.mjs` 保存本轮型号表与别名修正依据，`scripts/catalog-publication-policy.mjs` 负责规格纠正和选材准入，`data/catalog/review-searches.json` 保存检索线索。`englishName` 是第二行显示名称。第一行保持规范名称，第二行使用官方英文型号或明确的英文功能名；尚未确认的库存名不编造官方译名。名称下方不再显示类别、单位、核验状态或说明；图标在左，系列标签与加入按钮在右。

`data/catalog/published.v5.json` 仅含发布条目；完整目录与审核档案继续保留旧 ID。新建推荐、手动加入、替换和系统自动补齐均遵守发布边界。恢复旧项目时保留原有器材、数量、备注与决策。系统缺项涉及已归档的具体型号时，保留核对提示并关闭该项自动补齐。

核验涵盖器材身份和名称内已有规格。未记录的卡口、套装附件、供应商价格、租赁单位和内部成本等级不能据此称为厂商已确认数据；涉及实际装配仍需要项目测试。

## V6 卡片显示与技术指标

V6 卡片显示顺序为“中文品牌名（有据时）+ 英文品牌名 + 产品系列 + 型号及完整规格 + 已确认的行业俗称”。通用用品省略“通用”品牌前缀；没有独立系列或型号时保留已有指代，不补造型号。MP、SP、UP 使用已有人工审核映射追加在对应 ARRI 镜头系列之后，其他搜索别名不自动当作俗称。

器材名下方使用最多三个代表性技术指标，右侧只保留加入操作。`englishName` 继续供搜索和历史资料使用。新显示字段不改变规范目录的稳定 ID、别名、重定向、规格差异或旧项目数量和备注。

指标依据按品类保存在 `data/catalog/card-specs-v6-camera.json`、`card-specs-v6-lenses.json`、`card-specs-v6-lighting.json`、`card-specs-v6-grip.json`。每个指标记录名称、值、来源、厂商或库存证据，以及型号或系列适用范围。用户确认：没有具体型号但能确认系列时，保留该记录并显示系列指标。系列指标必须有 `scope: "series"` 和 `seriesLabel`，界面通过指标的悬停说明保留“系列参考”及适用范围；不得把某个具体型号的能力默认为整个系列或未指定代际的库存实物能力。

当前规范名称中明确的规格可作为库存证据，不能从型号数字猜测尺寸、功率、承重或卡口。变焦倍率可由明确的焦距范围计算，不能把密度和对应减光档数等同一参数换算拆成两项凑数。改装镜头保留改装标识，套组不以全系列焦段范围冒充实际套组组成。

用户于 2026-10-17 补充确认：无法辨识品牌或系列的记录可以保留已确认指标；随后要求未确定的指标在界面留空，不显示额外提示。因此不以通用类别知识、相近型号或重复换算凑足三项。已检索但原厂公开资料仍不足的记录，同样明确保留缺口，不声称规格已完整核验。

`scripts/catalog-card-specs.mjs` 随 `catalog:build` 生成卡片显示数据与逐 ID 缺口报告 `data/catalog/card-specs-v6-audit.json`；来源与审核说明不打包到前端。`catalog:check` 检查输出一致性；`catalog:cards:check` 要求全部记录已研究，允许有真实原因的 `identity-required` 或 `source-unavailable` 缺口，拒绝 `research-pending`。`catalog:cards:complete` 则严格要求每条都有三个指标，保留为后续全库完整性检查。具体型号的显示名修正使用有来源及理由的 `displayName`，不修改旧 ID；规范目录的底层版本仍单独维护。

## V5.1复核入口

`data/catalog/catalog-additions.v5.1.json` 保存本轮新增型号和尺寸项，`data/catalog/review.v5.1.json` 保存逐品牌结论、名称补丁、官方来源、昵称和上市判定。品牌级资料仅支持品牌，不升级型号核验；第三方改装和历史库存配置不得仅凭现代系列页改成原厂规格。`data/catalog/v5-baseline-identities.json` 是V5稳定身份及旧名快照，用于验证恢复与搜索兼容性。

未上市产品不进入规范目录或发布目录，只在审核报告说明。官网Backorder需结合上市资料判断，不等同未上市。新增具体型号的`inventoryAvailability`为`unconfirmed`，不虚构租赁库存。原生卡口有依据时显式记录；厂商提供多卡口版本但库存配置未知时保持`unknown`，不得按品牌推断PL。版本由`data/catalog/release-metadata.json`统一用于生成数据、界面和分享元数据。
